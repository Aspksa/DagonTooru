# Дракончик Тоору

Первый работающий локальный этап проекта по [полной спецификации](docs/DRAGON_TOORU_MASTER_SPEC.json). Одно ядро на Python, локальный веб-интерфейс и SQLite. Интерфейс открывается на `http://127.0.0.1:8765/`. Сервер слушает только локальный компьютер; публикация в интернет не реализована.

## Запуск

Нужен Python 3.10+; зависимости Python не требуются. На Windows запустите `ДракончикТоору.bat`. Папка `runtime/python/python.exe` имеет приоритет, поэтому проект может работать с внешнего SSD без системного Python. `SETUP.bat` пока только объясняет подготовку portable Python; автоматическая проверяемая загрузка ещё не реализована.

Запуск через терминал: `python -m core.server` из корня репозитория. Остановить сервер: Ctrl+C в его окне.

Ядро защищено от второго экземпляра. `core/instance.py` удерживает системную файловую блокировку `runtime_state/core.lock`; повторный процесс останавливается до открытия SQLite. После завершения процесса ОС освобождает блокировку автоматически.

Launcher проверяет уже работающую Тоору командой `python -m core.server --probe`. Probe обращается к `/api/v1/system/identity` и проверяет service id `dragon-tooru-core`, поэтому посторонний HTTP-сервис на порту 8765 не считается ядром Тоору.

Локальный AI по умолчанию использует Ollama на `http://127.0.0.1:11435` и модель `tooru-local:4b`. Удалённый адрес AI не разрешён. Без модели проекты и память работают, а диалог покажет понятную ошибку. Модель не скачивается автоматически.

Данные находятся в `database/tooru.db` рядом с программой и игнорируются Git. Схема базы управляется файлами `database/migrations/NNN_*.sql`; текущая версия схемы — 1.

В «Настройках» можно создать согласованную копию базы во время работы сайта: файлы `.db` и `.db.sha256` появятся в `backups/`. Backend восстановления реализован через `POST /api/v1/backups/restore`: перед восстановлением проверяются SHA-256, целостность SQLite и совместимость схемы, затем создаётся safety-backup текущей базы. Отдельного UI восстановления пока нет.

## Текущие возможности

- Личный диалог с локальным Ollama и личным контекстом памяти.
- Раздельные personal/home/work области памяти и память проектов.
- Два исходных рабочих проекта и создание новых домашних/рабочих проектов.
- Локальная диагностика ядра, базы, версии схемы, свободного места и Ollama.
- Миграции SQLite.
- Резервная копия SQLite с проверкой целостности и SHA-256.
- Проверенное восстановление SQLite с safety-backup.
- Защита одного экземпляра Tooru Core и identity probe.
- Адаптивный веб-интерфейс на русском языке.

Почта, Internet Gateway, мобильные приложения, учётные записи, публичный сервер, автоматическая установка portable Python, полный Backup Manager, Crash Recovery/Safe Mode, обновление через GitHub и криптографические подписи пока **не реализованы**. Фактическое состояние находится в `ИСТОРИЯ/`.

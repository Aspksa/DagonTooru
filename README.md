# Дракончик Тоору

Первый работающий локальный этап проекта по [полной спецификации](docs/DRAGON_TOORU_MASTER_SPEC.json). Одно ядро на Python, локальный веб-интерфейс и SQLite. Интерфейс открывается на `http://127.0.0.1:8765/`. Сервер слушает только локальный компьютер; публикация в интернет не реализована.

## Запуск

Нужен Python 3.10+; зависимости Python не требуются. На Windows запустите `ДракончикТоору.bat`. Папка `runtime/python/python.exe` имеет приоритет, поэтому проект может работать с внешнего SSD без системного Python. `SETUP.bat` сообщает, как подготовить переносимый Python; автоматическая загрузка пока не реализована. Запуск через терминал: `python -m core.server` из корня репозитория. Остановить сервер: Ctrl+C в его окне.

Локальный AI по умолчанию использует Ollama на `http://127.0.0.1:11435` и модель `tooru-local:4b`. Удалённый адрес AI не разрешён. Без модели проекты и память работают, а диалог покажет понятную ошибку. Модель не скачивается автоматически.

Ответ ограничен 256 токенами, генерация подробных рассуждений отключена в запросе и занимает до двух минут, включая загрузку модели.

Данные находятся в `database/tooru.db` рядом с программой и игнорируются Git. Схема базы управляется файлами `database/migrations/NNN_*.sql`; текущая версия схемы — 1.

В «Настройках» можно создать согласованную копию базы во время работы сайта: файлы `.db` и `.db.sha256` появятся в `backups/`. В ней сохраняются проекты и память. Для защиты от поломки SSD скопируйте оба файла на другой носитель.

Backend восстановления реализован через `POST /api/v1/backups/restore`. Перед восстановлением проверяются SHA-256, целостность SQLite и совместимость схемы, затем автоматически создаётся safety-backup текущей базы. Отдельного UI восстановления пока нет. Полный Backup Manager для файлов проектов, настроек и других защищаемых каталогов ещё не реализован.

Не запускайте одну базу напрямую с нескольких компьютеров через сетевой диск.

## Текущие возможности

- Личный диалог с локальным Ollama и личным контекстом памяти.
- Раздельные личная, домашняя и рабочая области памяти; у проектов собственные записи.
- Два исходных рабочих проекта и создание новых домашних/рабочих проектов.
- Локальная диагностика ядра, базы, версии схемы, свободного места и Ollama.
- Миграции SQLite с `PRAGMA user_version`.
- Резервная копия базы с проверкой целостности и SHA-256.
- Проверенное восстановление SQLite с safety-backup.
- Адаптивный веб-интерфейс на русском языке.

Почта, Internet Gateway, мобильные приложения, учётные записи, публичный сервер, обновление через GitHub, автоматическая установка Python, полный Backup Manager, защита второго экземпляра и криптографические подписи пока **не реализованы**. Полный список и фактическое состояние находятся в `ИСТОРИЯ/`.

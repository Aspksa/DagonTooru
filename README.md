# Дракончик Тоору



Первый работающий локальный этап проекта по [полной спецификации](docs/DRAGON_TOORU_MASTER_SPEC.json). Одно ядро на Python, локальный веб-интерфейс и SQLite. Интерфейс открывается на `http://127.0.0.1:8765/`. Сервер слушает только локальный компьютер; публикация в интернет не реализована.

## Запуск

Нужен Python 3.10+; зависимости Python не требуются. На Windows запустите `ДракончикТоору.bat`. Папка `runtime/python/python.exe` имеет приоритет, поэтому проект может работать с внешнего SSD без системного Python. `SETUP.bat` сообщает, как подготовить переносимый Python; автоматическая загрузка пока не реализована. Запуск через терминал: `python -m core.server` из корня репозитория. Остановить сервер: Ctrl+C в его окне.

Локальный AI по умолчанию использует Ollama на `http://127.0.0.1:11435` и модель `tooru-local:4b` — параметры установки Тоору на внешнем SSD. Оставьте окно сервера AI открытым и **перезапустите окно Tooru Core** после обновления кода, затем снова запустите `.bat`. Открытый ранее сервер продолжает работать со старым кодом. Для другой локальной установки перед запуском можно задать `TOORU_OLLAMA_URL` и `TOORU_MODEL` в окружении. Например: `set TOORU_OLLAMA_URL=http://127.0.0.1:11434` и `set TOORU_MODEL=имя_модели`. Удалённый адрес AI не разрешён. Без модели проекты и память работают, а диалог покажет понятную ошибку. Модель не скачивается автоматически.

Ответ ограничен 256 токенами, генерация подробных рассуждений отключена в запросе и занимает до двух минут, включая загрузку модели. Во время ожидания диалог показывает статус. Если ответ не пришёл, проверьте окно AI server; после обновления обязательно перезапустите Tooru Core, иначе он продолжит использовать прежний лимит в 90 секунд.

Данные находятся в `database/tooru.db` рядом с программой и игнорируются Git. Скопируйте файл базы отдельно для резервной копии после остановки ядра. Не запускайте одну базу напрямую с нескольких компьютеров через сетевой диск.

## Текущие возможности

- Личный диалог с локальным Ollama и личным контекстом памяти.
- Раздельные личная, домашняя и рабочая области памяти; у проектов собственные записи.
- Два исходных рабочих проекта и создание новых домашних/рабочих проектов.
- Локальная диагностика ядра, базы, свободного места и Ollama.
- Адаптивный веб-интерфейс на русском языке.

Почта, интернет-агент, мобильные приложения, учётные записи, публичный сервер, обновление через GitHub, автоматическая установка Python, резервирование и криптографические подписи пока **не реализованы**. Разделы в интерфейсе показывают статус планов. Полный список и фактическое состояние находятся в `ИСТОРИЯ/`.

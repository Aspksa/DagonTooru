# Известные ограничения

Автор: Матиенко Антон Александрович · Aspksa@yandex.ru

- Portable Python installer остаётся IN_PROGRESS до фактической проверки на Windows и внешнем SSD.
- Базовый Crash Recovery реализован и протестирован в Linux, но реальное аварийное завершение/повторный запуск на пользовательской Windows/SSD ещё не подтверждены.
- Crash Recovery сейчас автоматически проверяет SQLite. Safe Mode и Maintenance Mode ещё не реализованы, поэтому при recovery error обычный запуск прекращается без отдельного минимального режима.
- Single-instance protection проверена на Linux, но `msvcrt.locking`, повторный launcher и полный сценарий конфликта `TOORU_PORT` требуют практической Windows-проверки.
- `runtime_state/core.lock` после аварийного завершения может содержать старое диагностическое состояние `running`; это не блокирует новый запуск, потому что источником истины является OS-level lock.
- При конфликте рабочего порта новый процесс должен завершиться до изменения `state.json` и до открытия SQLite; это покрыто Linux-тестом, но ещё не проверено на целевой Windows.
- Backup Manager пока охватывает только SQLite; проекты, пользовательские настройки и другие защищаемые каталоги ещё не входят в полный backup.
- Linux-регрессия на Python 3.13 выдаёт `ResourceWarning` о незакрытых SQLite connection во время существующих backup/restore тестов. Ошибок тестов нет, но lifecycle соединений требует отдельной проверки.
- Для диалога нужен отдельно установленный и запущенный Ollama с выбранной моделью.
- Авторизация отсутствует; сервер предназначен только для localhost.

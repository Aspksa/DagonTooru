# Решения

Автор: Матиенко Антон Александрович · Aspksa@yandex.ru

- На первом этапе Python стандартной библиотеки позволяет запустить ядро без установки пакетов.
- Локальный сервер связывается только с 127.0.0.1; POST требует same-origin и JSON. Публичный доступ потребует отдельной архитектуры аутентификации.
- Контекст памяти выбирается явно; память другого проекта не попадает в запрос к модели.
- Текст авторства в исходниках не считается подписью Ed25519.
- Локальная Ollama по умолчанию слушает `127.0.0.1:11435`, модель — `tooru-local:4b`; удалённый AI адрес запрещён.
- Резервная копия SQLite создаётся online backup API, проверяется и сопровождается SHA-256.
- Изменения схемы SQLite выполняются только последовательными миграциями `database/migrations/NNN_*.sql`; номер схемы хранится в `PRAGMA user_version`.
- Перед восстановлением SQLite создаётся safety-backup; источник проверяется по SHA-256, `PRAGMA integrity_check` и совместимости схемы.
- Защита одного экземпляра строится на OS-level файловой блокировке, а не на PID-файле и не на факте занятого TCP-порта.
- Launcher определяет работающую Тоору через `/api/v1/system/identity` и service id `dragon-tooru-core`.
- TCP-порт занимается до инициализации Crash Recovery и `Storage`, чтобы конфликт со старым ядром или чужой программой не менял lifecycle state и не приводил к параллельному открытию или миграции SQLite.
- Crash Recovery хранит историю жизненного цикла в `runtime_state/state.json` отдельно от single-instance lock.
- `state.json` создаётся только после успешного захвата OS-lock и рабочего TCP-порта; запись выполняется атомарно через временный файл и `os.replace`.
- Необработанное исключение не помечается clean shutdown; следующий запуск обязан увидеть незавершённую сессию.
- После незавершённой или неизвестной предыдущей сессии ядро проверяет SQLite до обычного запуска HTTP-сервера. Ошибка recovery прекращает обычный запуск; автоматический Safe Mode остаётся отдельным следующим этапом.
- Portable Python устанавливается только из официального Python.org embeddable ZIP с зафиксированным SHA-256. Текущая закреплённая версия — Python 3.14.7.
- Поддерживаются AMD64, ARM64 и x86 Windows-пакеты. Архив сначала скачивается в `temp/`, проверяется, распаковывается в `runtime/python.new` и тестируется до замены рабочего runtime.
- Для распаковки используются штатные `curl.exe`, `certutil.exe` и `tar.exe`; PowerShell в штатной установке не используется.
- Штатный `python*._pth` embeddable runtime сохраняет изоляцию; в него добавляется только относительный путь `..\..` к корню проекта. `import site` автоматически не включается.
- Уже работающий совместимый `runtime/python/python.exe` не заменяется без необходимости.
